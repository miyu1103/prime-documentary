# Token Efficiency (binding on every thread, added 2026-08-16)

**測ってから書いた。推測は入っていない。** 大きいセッション5本の実測:

```
会話の中身 ...........      6,047,218 トークン（推定）
実際の請求 ........... 8,801,355,788 トークン
増幅率 ...............         約1,455倍
うち cache_read ......             95%
うち Claude の出力 ...            0.2%
```

**Claude が書く文章（設計書・台本・散文）は請求の 0.2%。ここを削っても何も安くならない。**
高いのは「1回の呼び出しの大きさ」ではなく「文脈の大きさ × 残りターン数」。
100ターン目に足した800字は、そのセッションの残り4,900ターン全部で再課金される。

`py -3.11 scripts/token_audit.py --live` がいつでも現在地を出す。

## 削ってはいけないもの（コストを理由に落とすのは禁止）

これらは品質そのもの。ここを削るのは節約ではなく劣化であり、rule 19 と invariant 13 に反する。

- **画像の目視QC**（コンタクトシート・shipped frames・プレート verdict）。
  `pd-factory-shelf-mislabeled` と EP64 memphis は、見なかったから起きた。
- 設計書・エピソード散文・`episode_spec` の記述量。
- 台本の3回パスと fact ledger の照合。
- `check_final_acceptance` / `check_spec_satisfied` / `check_packaging_claims` の実行。
- 実測してから断定する手順そのもの（`feedback_measure_before_explaining`）。

**節約はムダの側からのみ取る。緑を早く出すために測定を省くのは、この規則の違反。**

## 1. セッションは工程で切る（最大の効果・制作に一切影響しない）

実測: 平均文脈 538,635 トークン × 5,004 ターン = 1セッション27億トークン。
ターン数を分ければ請求はほぼ比例して落ちる。5分割で約1/5。

- 工程の境目で切る: **調査 / 台本 / 画像 / 組み立て / レンダ / QC / 投稿**。
- 切る前に必ず `docs/HANDOVER.md` を更新する（既存の義務。CLAUDE.md 冒頭）。
  チャットログにしか無い引き継ぎは無いのと同じ、という規則がそのまま節約手段になっている。
- `token_audit.py --live` が `CRIT`（平均30万超）を出したら、次の工程の頭で必ず切る。
- **作業の途中では切らない。** 中断による作り直しの方が高くつく。

## 2. シェルは「大きさ」でなく「回数 × 残りターン」で考える

実測: Bash/PowerShell が文脈の43%。しかも **入力(25%) > 出力(21%)** —
長いインライン heredoc を毎回打ち直しているのが効いている。

- **2回以上打つ Python heredoc は `scripts/` のファイルにする。** 3行の呼び出しで済む。
- 出力は既定で絞る: `| head -30` / `| tail -20` / 件数と差分だけを print。
  ファイル全文・全件リストを端末に出さない。必要なら書き出して Read で必要行だけ読む。
- `sed -n '1,400p'` のような全文ダンプの代わりに Grep か Read の `offset`/`limit`。
- 独立した確認は1コマンドにまとめる（`&&` で連結して1回で返す）。
- **レンダ・長時間ジョブをポーリングしない。** `run_in_background` の完了通知か Monitor を使う。
  実測で `node ...` 122回、`taskkill/pkill` 系の生存確認が上位を占めていた。

## 3. 探索・調査・目視QCはサブエージェントに出す

実測: Agent は46回使って文脈の3.3%しか占めていない。試行錯誤が親に残らないため。

- 素材探索、ログ調査、`grep` の広い掃き出し、コンタクトシートの目視QC、
  複数ファイルにまたがる確認は Agent に投げ、**結論だけ**を受け取る。
- **QCの厳しさは落とさない。** 見る枚数は同じで、置き場所を変えるだけ。
- 画像は1枚あたり約1,500トークン固定。**タイル数が増えてもコンタクトシート1枚の値段は変わらない**ので、
  個別に読むより1枚に詰めた方が常に安い。これは品質と両立する。

## 4. Write より Edit

実測: Write の入力が文脈の10-13%。既存ファイルの全文再生成は、その全文を文脈に置くのと同じ。

- 既存ファイルの変更は `scripts/pd_edit.py`（rule 4.5 で既に義務）。差分だけが文脈に載る。
- 新規の大きい生成物は、文脈に本文を通さずスクリプトに書かせる。

## 検証

この規則は `scripts/token_audit.py` で検算できる。数字が出ない主張はこの規則に書かない。
セッション終了時に `--live` を回し、平均文脈と増幅率を `docs/handover/YYYY-MM-DD.md` に1行残すこと。
