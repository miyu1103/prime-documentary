# HANDOVER — read this first

This is the standing entry point for any session picking up Prime Documentary. It has two halves and
they are trusted differently.

- **LIVE STATE** below is generated by `py -3.11 scripts/handover_snapshot.py`. It is measurement.
  Regenerate it whenever you doubt it. If it contradicts anything written in prose anywhere in this
  repository, including the narrative below, **the measurement wins.**
- **The narrative** is the judgement, the traps and the reasons — the part a machine cannot produce.
  The current one is linked at the bottom; older ones stay in `docs/handover/`.

The channel brief prints itself. A `SessionStart` hook runs `scripts/pd_brief.py` at the top of
every session, so what is decided, what is being measured and what may not be touched arrive
without anyone typing anything. `--full` when you want the sources and the reasoning.

Three commands to run before doing anything:

```
py -3.11 scripts/handover_snapshot.py        # refresh the block below, then read it
py -3.11 scripts/check_queue_will_stall.py   # every reason the render queue would stall
py -3.11 scripts/check_doc_contradictions.py # the binding documents still agree with each other
```

It reads `config/pd_experiments.v001.json`, which is **the only copy** of the channel's
measured figures, its running experiments, their read dates, and the video ids that must not be
retitled or re-thumbnailed. Prose in this repository no longer holds those numbers.
`scripts/apply_title_batch.py` refuses a write that lands in a running experiment — but nothing
can see a change made by hand in the Studio UI, so read the brief before opening Studio.

**Session-ending protocol.** Before a session ends, run `handover_snapshot.py`, then write that
session's narrative to `docs/handover/YYYY-MM-DD.md` and point the link at the bottom of this file
at it. A handover that only exists in a chat log does not exist.

## Permanent operating rules that keep getting rediscovered

These are not tonight's news. They are the things that cost days when a fresh session did not know
them, so they live here rather than in a dated file.

1. **Exactly one session operates the publishing calendar** — uploads, scheduling, rearranging.
   Whoever holds this handover holds that role. Never run a second thread that also schedules. A
   `publishAt` in the past publishes immediately.
2. **Never edit a shell script while bash is executing it.** Bash reads a running script by byte
   offset; an edit mid-flight corrupts execution. This already destroyed one episode's step 7. The
   unattended queue copies `_finish_episode.sh` to a snapshot at startup for exactly this reason —
   which also means **a fix to the original does not reach a queue that is already running.**
3. **A checker that disagrees with a working pipeline is wrong until proven otherwise.** Measure the
   instrument before believing it. Real examples, all from one night: a check reported "no narration"
   for all seven episodes because it globbed `*.wav` when the real artifact is
   `narration_index.v001.json`; a duplicate-queue detector reported "0 snapshots" with a queue plainly
   running, because Python reads a literal `/tmp` as `C:\tmp` while Git Bash maps it to `%TEMP%`; and
   a quota `record()` call multiplied 3,500 by 35 because its `units` argument is per-call.
4. **Never weaken a threshold, gate, schema or declared spec value to make something pass.** If it
   cannot pass, say so with the numbers and let it be an owner decision.
5. **A gate that has never been shown to fail is decoration.** When you add or fix one, demonstrate it
   rejecting a deliberately bad input before relying on it.
6. **Fix everything in one batch before re-rendering.** A render is ~3 hours. Run
   `py -3.11 scripts/predict_acceptance.py --slug <slug>` first — it forecasts acceptance failures
   without spending the GPU. Several of its predictions self-clear inside the finisher; read
   `_finish_episode.sh` to see which, rather than hand-fixing them.
7. **The GPU takes exactly one job.** i2v and a render cannot overlap. i2v is ~206 s per clip; a
   30-minute render is ~3 h.
8. **Stale receipts lie.** Before acting on any receipt, check which file it measured and when. Two
   agents in one night went down blind alleys on two-day-old receipts.
9. **Resume a dead agent, do not respawn it.** When the API session limit kills agents — it kills all
   of them at once — resuming from the transcript keeps everything they measured. A fresh agent
   starts from nothing.
10. Reply to the owner in Japanese. Artifacts in English.
