# ショート → 長尺 導線設計（v001・2026-08-03 実装済み）

他スレッドへの共有用。**この文書の指示は実装済みで、コードとして動いている**。設計案ではない。

---

## 1. なぜ必要だったか（実測）

2026-08-02 に実チャンネルを測った結果。

| 測定項目 | 値 |
|---|---|
| 公開済みショート | 46 本 |
| そのうち長尺へのリンクを持つもの | **0 本** |
| それらのショートの累計再生 | 4,391 回 |
| ショートの登録転換 | 1,000 再生あたり 0.77 人 |
| 長尺の登録転換 | 1,000 再生あたり **3.67 人** |

**長尺は 1 再生あたり約 4.8 倍の登録転換率**。にもかかわらず、ショートを見た 4,391 人には長尺へ行く道が一本も無かった。ショートは入口としては機能していたが、そこで行き止まりだった。

これが「入口○・変換✗」という診断の正体。

## 2. 導線は 5 層で作る

1 か所だけでは効かない。視聴者がどこで気づくか分からないので、全部置く。

### 層1: 説明欄の 1 行目（最重要・唯一の必須）

```
▶ FULL CASE: <長尺のタイトル>
https://www.youtube.com/watch?v=<VIDEO_ID>

（以下、通常の説明文）
```

- **1 行目**であること。ショートの説明欄は折り畳まれるので、2 行目以降は読まれない。
- タイトルを併記する。URL だけだと何に飛ぶか分からず押されない。
- 実装: `scripts/schedule_short_youtube.py` の `ensure_funnel_description()`

### 層2: 動画内の誘導カード（最後の約 2 秒）

- ループの締めカットに重ねる `▼ LINK BELOW` の帯。
- **偽のボタンにしない**。ショートは画面内の要素をタップできないので、押せそうな見た目は裏切りになる。「下にリンクがある」と指し示すだけにする。
- 背景の暗幕は `0.46`（初期値 `0.72` は絵を潰しすぎた）。
- 実装: `remotion/src/compositions/Short.tsx` の `isCta` / `ctaFadeOutSec`

### 層3: 固定コメント

```
<長尺に残した問い>

Full case here → https://www.youtube.com/watch?v=<VIDEO_ID>
```

`funnel_question_left_for_longform` をそのまま使う。設計段階で「ショートでは答えない問い」を必ず 1 つ残してあるので、それを固定コメントで再提示する。

### 層4: Studio の「関連動画」設定

**API では設定できない。**YouTube Studio で手作業。1 本あたり約 30 秒。
作業リスト: `episodes/_planning/SHORTS_RELATED_VIDEO_WORKLIST.v001.md`

### 層5: 構成そのもの（ループ）

最後のセリフが最初のセリフの意味に戻る作り。2 周目に入ると「答えが無い」ことに気づく → 説明欄を見る、という動線。

- 設計 JSON に `loop: true` と `loop_join`（どう戻すかの説明）を必須にしている。
- 締めのカットは冒頭の絵を逆順に replay して最後に 1 枚目へ戻る。継ぎ目が消える。

## 3. 機械で強制していること

**人間の記憶に頼らない。**忘れた瞬間に穴が開くので、コードが拒否する形にした。

### 3-1. 行き先が公開されていなければ投稿できない

`schedule_short_youtube.py` は、CONFIG に `longform` の動画 ID が無い、または
その動画が `public` でない場合、**アップロード自体を拒否**する。

```
raise SystemExit("this Short's CONFIG has no 'longform' video id. Every Short must name "
                 "the long-form it feeds before it can be uploaded.")
```

非公開の動画へのリンクは、リンクが無いより悪い（押すと見られない）。

### 3-2. 毎日の自動同期

`scripts/daily_funnel_sync.py` を 1 日 1 回走らせる。

- 既にリンクがあるショートは飛ばす
- 行き先がまだ非公開なら黙って飛ばし、翌日また試す
- `status` は絶対に送らない（送ると `publishAt` が壊れて即公開される）
- タイトル・タグ・カテゴリは読み直して同じ値で送り返す

長尺は 1 日 1 本公開されるので、**毎日どれかのショートが「リンク可能」になる**。手作業では続かない。

### 3-3. 既存分の一括埋め込み

`scripts/backfill_short_funnel.py` で公開済み 40 本に後から挿入済み。

## 4. ハマった罠（同じ轍を踏まないために）

### 罠1: YouTube のアップロード一覧 API は動画を取りこぼす

**実測 2026-08-03**: `playlistItems`（uploads プレイリスト）が 115 行返すのにユニークは 106 件。
**9 本が欠落**し、うち 3 本は公開済みの長尺だった。

結果として `daily_funnel_sync` が「行き先がまだ非公開」と誤判定し、
**公開済みショート 15 本が何日も行き止まりのまま**放置された。エラーは一切出ない。

対策: `scripts/yt_channel_index.py` を唯一の列挙口にし、
`playlistItems` と `search.list?forMine` の**和集合**を取る。食い違えば警告を出す。
`scripts/check_yt_enumeration.py` が、単一 API での列挙をコードレベルで禁止する。

**この取りこぼしは予約カレンダーが 2 日飛んでいた真因でもあった。**
取り残された 2 本が一覧に出ないので、日程を詰めるスクリプトから見えていなかった。

### 罠2: API の 1 日上限

`videos.insert` は 1 本 **1,600 ユニット**、日次上限 10,000。
つまり**アップロードは 1 日 6 本が物理上限**。35 本なら 6 日かかる。

読み取りだけでも枯れる。`search.list` は 1 ページ 100 ユニット。
監査ツールを 5 本続けて回して枯渇し、次の呼び出しが 403 になった。

対策: `scripts/yt_quota.py`。着手前に `assert_budget()` が計算して拒否する。
バッチが途中で死ぬのを防ぐ。

なお太平洋時間は夏時間で -7。固定 -8 にすると回復後 1 時間、自分で投稿を拒否する。

### 罠3: 音声で誘導しない

以前は「Watch the full case on the channel.」を最後に読み上げていた。
**46 本がこれを付けていて、45 本の登録転換がゼロだった。**

ループを切るうえに効果が無い。音声からは外し、カード・説明欄・固定コメントに移した。
`verify_short_designs.py` の `CTA_WORDS` が、締めのセリフに CTA 語が混ざると不合格にする。

（この検査は正規表現に制御文字が混入していて**一度も動いていなかった**。
シェルのヒアドキュメントが `\b` をバックスペース文字に変換していたのが原因。修復済み。）

## 5. 効果測定に使う指標

| 指標 | 意味 |
|---|---|
| 登録転換（1,000 再生あたり） | ショート 0.77 → 長尺 3.67。ここを埋めるのが目的 |
| ショートの説明欄クリック率 | Studio の「トラフィックソース」で長尺側から見る |
| 長尺の「Shorts フィードから」流入 | Studio の外部流入内訳 |

CTR とインプレッションは **API では取れない**（Studio のみ）。

---

## 6. 新しいショートを作るときのチェックリスト

1. 設計 JSON に `longform` の行き先を決めてあるか（公開済みか）
2. `funnel_question_left_for_longform` に、ショートでは答えない問いが 1 つあるか
3. `loop: true` と `loop_join` があるか
4. 締めのセリフに CTA 語が入っていないか（`verify_short_designs.py` が検査）
5. `schedule_short_youtube.py` の CONFIG に `longform` を書いたか
6. 投稿後、Studio で関連動画を手作業で設定したか（層4）

1〜5 は機械が拒否する。**6 だけが人力**。
