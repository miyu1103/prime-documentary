# TikTok アカウント作り直し（v2）— 立ち上げ手順と禁止事項

2026-08-16 オーナー決定。`@prime.documentary8`（v1）を捨てて新規に作り直す。
このファイルは**次に触る人が最初に読む1枚**。v1の失敗の記録は
`docs/PD_RETRO_20260810_TIKTOK_AND_CALENDAR.v001.md`、操作の罠は `scripts/tiktok/README.md`。

## 0. なぜ作り直すのか（2026-08-16 実測）

| 検査 | 結果 |
|---|---|
| 公開中15本の公開状態 | 公開されている（Cookieなしの oEmbed が全て 200） |
| その15本の再生数 | **全部 0**（いいね0・コメント0。3〜4日経過） |
| アカウント全体のインサイト | 動画の視聴 `--` / プロフィール表示 `--` / フォロワー **0** |
| 8/9 に削除した137本 | 記録上**全て 0 再生** |

**開設以来およそ152本、再生数の合計が 0。** 仕様変更なら「伸びが鈍る」形で出る。
きっちり 0 が152本続くのは、アカウント単位で配信されていない形。

**中身の問題ではない。振る舞いの問題。** v1がやったこと＝一晩で100本超アップロード →
137本を一括削除 → また大量アップロード。全て自動操作。プロフィール画像なし・自己紹介なし・
フォロワー0・自動生成風のユーザー名。スパム判定の教科書どおり。

**測れなかったこと（正直に）**: 自動操作のChromeからは `/search`・`/setting`・
プロフィールページが全て Akamai の `Access Denied` で弾かれる（TikTok Studio の管理画面だけ通る）。
よって「検索に出るか」「アカウントに制限が付いているか」は**Web からは確認できていない**。
確認できるのは**スマホアプリの「設定とプライバシー → アカウント → アカウントの状態」だけ**。

## 1. オーナーしかできないこと（ここが最初）

1. **スマホアプリで新規アカウントを作る。** 電話番号／メール認証が要るので自動化できない。
2. **v1と同じ端末・同じ回線で作らない方が安全。** 作成時はモバイル回線（Wi-Fi を切る）。
   v1のブラウザプロファイル `C:/temp/studio_auto/work_profile` は**二度と使わない**
   （Cookie と端末指紋で v1 と結び付く）。v2 用は別ディレクトリを新規に作る。
3. **作った直後に投稿しない。** プロフィールを埋めて、数日は普通のユーザーとして使う（§3）。

### 決めること

- **ユーザー名**: v1の `prime.documentary8` は自動生成風で、しかも TikTok が変更を受け付けなかった。
  v2 は**最初に確定させる**（後から変えられない前提で選ぶ）。候補:
  `primedocumentary` / `primedoc.cases` / `primedocumentary.tv`
  ※ TikTok の空き判定は v1 で嘘をついた実績がある（ありえない文字列でも「使えません」と出た）。
  アプリで実際に試すこと。
- **アイコン**: PD の既存ロゴを使う。空のままにしない。
- **自己紹介**: 例
  `Real cases. Court records only. New case every day.` ＋ YouTube への誘導1行。

## 2. 絶対にやらないこと（v1を殺した行動そのもの）

1. **一晩の大量アップロード禁止。** ランプ（§3）を超えない。
2. **一括削除禁止。** 失敗した投稿も消さずに残す。削除は1本ずつ、理由がある時だけ。
3. **1日の上限を回避しない。** `CHECK_LIMIT_REACHED` が出たら**その日は終わり**。
   翌日に持ち越す（完了済みは自動でスキップされる）。
4. **著作権チェックが緑になる前に送信しない**（チェック自体が止まる。BAN の最短経路）。
5. **全投稿に同じ末尾を付けない。** v1は152本すべてが
   `Full case on YouTube: @primedocumentarystudio #truecrime #lawtok #documentary #truestory`
   で終わっていた。同一の定型文が152本並ぶのは、それ自体がスパムの信号。
   §5 のとおり散らす。
6. **AI生成ラベルの確認を飛ばさない。** Remotion のコンテナコメントが原因で v1 の127本に
   「AI生成」バッジが付いた。`render_shorts_tiktok.sh` が `-map_metadata -1` で除去済みだが、
   アップローダー側のスイッチを毎回読み直すこと（スクリプトは実装済み）。

## 3. 立ち上げランプ（14日）

**自動投稿は最初の1週間は使わない。** 手で投げる。ここを急ぐと v1 と同じ場所に戻る。

| 日 | 投稿数 | やり方 | 併せてやること |
|---|---|---|---|
| 1〜3 | **0本** | 投稿しない | プロフィール完成。1日5〜10分アプリを普通に見る。数アカウントをフォロー |
| 4〜6 | **1本/日** | スマホから手動 | コメントが付いたら返す |
| 7〜9 | **2本/日** | 手動 or `schedule_shorts_tiktok.js ... 2`（MAX=2） | 48時間後の再生数を記録 |
| 10〜14 | **3本/日** | 自動可 | 同上 |
| 15日〜 | **4本/日**（10:00/14:00/18:00/22:00 JST） | 自動 | v1 と同じ本数に戻すのはここから |

**撤退基準（先に決めておく）**: 4〜6日目に投げた3本が **48時間経っても全て0再生**なら、
そこで止めて原因を洗う。**在庫169本を流し込まない。**動画の初公開は1回きりで、
配信されないアカウントに投げた分は捨てたのと同じ。

## 5. 投稿の中身のルール

- **キャプションは1本ずつ違う書き出しにする。** 定型の末尾を全部に付けない。
- **ハッシュタグは3〜5個、毎回同じ組み合わせにしない。** 動画の題材に合うものを選ぶ
  （`#lawtok` を全部に付けない）。スラッグ由来の造語タグは定義上リーチ0なので使わない。
- **カバーは必ず設定する。** アップロード完了（`アップロード完了` の表示）を待ってから。
  57%時点の編集画面で入れても、処理完了時に TikTok の自動フレームで上書きされる。
  投稿後は**変更できない**（編集アイコンが全部 `cursor: not-allowed`）。
- **YouTube への誘導はキャプション末尾のテキストのみ**（リンクは貼れない）。毎回同じ文にしない。

## 6. ツール側でやること（v2 切り替え）

現行スクリプトはそのまま使える。切り替えるのは**状態ファイルと Chrome プロファイル**だけ。

```
# 1. v2 用の Chrome プロファイル（work_profile は v1 のもの。使い回さない）
#    scripts/tiktok/start_chrome.js の --user-data-dir を v2 用に変える
# 2. 投稿台帳をリセット（v1 の SCHEDULED を引き継ぐと v2 で全部スキップされる）
mv C:/temp/studio_auto/tt_clean_result.jsonl C:/temp/studio_auto/tt_clean_result.v1.jsonl
# 3. 1日の本数はランプに合わせて MAX 引数で絞る（既定6は使わない）
node scripts/tiktok/schedule_shorts_tiktok.js <開始日> 0 <MAX>
```

**Windows タスクによる自動化は、15日目に再生数が 0 でないことを確認してから。**
YouTube 側（`PD-ShortsPush`）と違い、TikTok は実ブラウザ操作＋1日上限があるため、
無人で回して失敗が積み上がる形にしない。

## 8. この文書の限界（正直に）

TikTok は判定の理由を公開しない。**「スパム判定である」ことを直接証明した測定は無い。**
あるのは「152本すべて0再生」「公開はされている」「振る舞いが典型的な引き金と一致する」の3点。
アカウントの状態はアプリでしか読めないので、**オーナーがアプリで確認した内容が最上位の証拠**になる。
そこに別の理由（例: 地域制限、年齢設定、認証未完了）が書いてあれば、この文書より**それが正しい**。
