よって「検索に出るか」「アカウントに制限が付いているか」は**Web からは確認できていない**。
確認できるのは**スマホアプリの「設定とプライバシー → アカウント → アカウントの状態」だけ**。

## 2. 絶対にやらないこと（v1を殺した行動そのもの）

1. **一晩の大量アップロード禁止。** ランプ（§3）を超えない。
2. **一括削除禁止。** 失敗した投稿も消さずに残す。削除は1本ずつ、理由がある時だけ。
3. **1日の上限を回避しない。** `CHECK_LIMIT_REACHED` が出たら**その日は終わり**。
   翌日に持ち越す（完了済みは自動でスキップされる）。
4. **著作権チェックが緑になる前に送信しない**（チェック自体が止まる。BAN の最短経路）。
5. **全投稿に同じ末尾を付けない。** v1は152本すべてが
   `Full case on YouTube: @primedocumentarystudio #truecrime #lawtok #documentary #truestory`
   で終わっていた。同一の定型文が152本並ぶのは、それ自体がスパムの信号。
   §5 のとおり散らす。
6. **AI生成ラベルの確認を飛ばさない。** Remotion のコンテナコメントが原因で v1 の127本に
   「AI生成」バッジが付いた。`render_shorts_tiktok.sh` が `-map_metadata -1` で除去済みだが、
   アップローダー側のスイッチを毎回読み直すこと（スクリプトは実装済み）。

## 5. 投稿の中身のルール

- **キャプションは1本ずつ違う書き出しにする。** 定型の末尾を全部に付けない。
- **ハッシュタグは3〜5個、毎回同じ組み合わせにしない。** 動画の題材に合うものを選ぶ
  （`#lawtok` を全部に付けない）。スラッグ由来の造語タグは定義上リーチ0なので使わない。
- **カバーは必ず設定する。** アップロード完了（`アップロード完了` の表示）を待ってから。
  57%時点の編集画面で入れても、処理完了時に TikTok の自動フレームで上書きされる。
  投稿後は**変更できない**（編集アイコンが全部 `cursor: not-allowed`）。
- **YouTube への誘導はキャプション末尾のテキストのみ**（リンクは貼れない）。毎回同じ文にしない。

### キュー作り直しで踏んだ罠（2回とも投稿前に捕まえた）

1. **`cover` を落とすと取り返しがつかない。** 最初の版は short/file/caption だけを書き出していて、
   `cover` と `risk` が消えていた。カバー無しで投稿された動画は**後からカバーを付けられない**
   （削除して上げ直すしかない）。今は元の行を丸ごと引き継ぎ、
   `--check` が「カバーがディスクに無い行」を数えて報告する。
2. **出力を入力にしない。** `SRC` を `tt_queue.json` にしていたため、一度上書きすると
   ビルダーが自分の出力を読み、失った項目は二度と戻らなかった。`SRC` は
   `tt_queue.v1_captions.json`（v1 の原本・不変）に固定した。

**Windows タスクによる自動化は、15日目に再生数が 0 でないことを確認してから。**
YouTube 側（`PD-ShortsPush`）と違い、TikTok は実ブラウザ操作＋1日上限があるため、
無人で回して失敗が積み上がる形にしない。

## 8. この文書の限界（正直に）

TikTok は判定の理由を公開しない。**「スパム判定である」ことを直接証明した測定は無い。**
あるのは「152本すべて0再生」「公開はされている」「振る舞いが典型的な引き金と一致する」の3点。
アカウントの状態はアプリでしか読めないので、**オーナーがアプリで確認した内容が最上位の証拠**になる。
そこに別の理由（例: 地域制限、年齢設定、認証未完了）が書いてあれば、この文書より**それが正しい**。
