## A. 実害が出たもの

### A-1. GPUの競合を見ずにレンダーを起動した
i2v が4090を100%使っている最中に Remotion を走らせ、**13,293フレーム（約40分）を捨てた。**
ゲート（`_finish_episode.sh` の `[2/4] GPU ready`）は正しく検出して abort したが、
私が事前に `nvidia-smi` を1回叩いていれば起きなかった。

→ **防ぎ方**: 重いジョブの前に GPU・ディスク・RAM・APIユニットを1コマンドで測る。
`nvidia-smi --query-gpu=memory.free,utilization.gpu --format=csv,noheader`

### A-2. ログの「DONE」を日付を見ずに読んだ
`[finish:norfolk] DONE` を見て「完了」と報告したが、**6日前の実行分**だった。
morton も同じ。「3本レンダー完了」は誤報で、実際に焼けていたのは flowers 1本。
**古いマスターを審査しかけた。**

→ **防ぎ方**: 完了判定はログ文字列ではなく**成果物のタイムスタンプ**で行う。
`stat -c %y <master>` を必ず見る。

### A-3. 公開状況をローカルファイルから読んだ
「8/14 tlo・8/15 atwater は埋まっている」と報告。**両方すでに公開済み**だった。
`youtube_schedule_result.v*.json` の `publish_at` は更新されない。

→ **防ぎ方**: 公開状況は**必ずチャンネルAPI**。`runs/_cache/yt_channel_index.json` も
古くなるので、新規アップロード後は該当IDを直接 `videos?part=status` で引く。
（記憶にも「ローカルでなくAPIを正とする。過去に誤答した実績あり」と書いてあったのに再発させた。）

### A-4. きれいなエピソードを誤って予約から外した
robosigning のカード時刻を**画面時刻だと思い込んだ**。実際は `film.json` の figure `start` は
**ナレーション基準**で、画面時刻は `+ hookSeconds + 3.5`（この話では +11.5秒）。
1つ前のカードのフレームを見て「女性の顔に名札が乗っている」と誤判定し、
**1時間、公開可能な動画を止めた。** 正しい時刻で4枚とも開いたら、箱・ドアノブ・手・家の上だった。

→ **防ぎ方**: フレームを抜く前にオフセットを計算する。
`screen = figure.start + film.hookSeconds + 3.5`。**抜いたフレームにカードが写っているかを
必ず目視で確認**してから判定する（写っていなければオフセットが間違っている）。

### A-5. キューを多重起動してレンダーを3本並行させた
ロックはまさにこれを防ぐためにある。私が消して再起動を繰り返した。全部遅くなった。

→ **防ぎ方**: 再起動前に必ず `pkill -9 -f render_queue.sh` → ロック確認 → 起動。
起動後に `ps -ef | grep -c "[r]ender_queue.sh"` が 1 であることを確認する。

### A-6. ディスクを見ずにレンダーを再投入した
willingham が2回失敗。エラーは `Timed out after 30000ms while setting up the headless browser`。
真因は **C:の空きが31GB（1.9TB中99%使用）** で、ブラウザの一時領域が作れないこと。
RAMもGPUも余裕があったので資源を疑っていなかった。

→ **防ぎ方**: レンダー失敗のブラウザ系タイムアウトは、まず `df -h /c` と TEMP のサイズを見る。
`TEMP` は 101.9GB あり、うち **77.3GB が `Adobe`**（After Effects の一時領域）だった。

## B. 計測器そのものを間違えた（3回）

### B-1. プロセス検索が自分自身に一致した
`Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'comfy' }` が
**自分のコマンドライン**に当たり、「ComfyUIが復活し続ける」と誤診断した。
ポート8188で判定し直したら閉じていた。
**同じ罠をサブエージェントが数時間前に報告していたのに、私が踏んだ。**

→ **防ぎ方**: プロセスの存否は**ポート**（`socket.connect`）か
`nvidia-smi --query-compute-apps` で判定する。コマンドライン検索は最後の手段。

### B-2. `kill -0` が死んだWindowsプロセスを「生きている」と返した
Git Bash の仕様。`render_queue.sh` の stale-lock 判定がこれだったため、
**終了済みプロセスのロックを50分待ち続けた。**

→ **修正済み**: `tasklist //FI "PID eq $pid"` に変更（`render_queue.sh` 32-35行）。
他の場所で生存確認を書くときも `kill -0` を使わない。

### B-3. 自分が作った検査を、落ちない作りにした
per-source カバー率の検査が、**「読んだと申告されたシート」ではなく
「フォルダに存在するフレーム全部」**を数えていた。シートを1枚外しても 303/303 と出た。

これは同じ日に `write_factory_clip_qc.py` で直した**まったく同じ欠陥**——
「見た証拠」ではなく「証拠の存在」を数える——を、私が新しく作り込んだもの。
**CLAUDE.md §4.6「落ちることを見せていない検査は飾り」がなければ、そのまま出荷していた。**

→ **修正済み**: シート名から連番を取り、そのシートが担当するタイル範囲だけを数える
（`check_shipped_frames.py` の `coverage_mode: per_source` ブロック）。
両方向（全枚→PASS / 1枚欠→NOT A PASS）で実証済み。

## C. 過去の失敗を再生産しかけた

### C-1. 存在しない関数名を書いた
`--replaces` の実装で `_http_get_json` を呼んだが、**この名前が存在しないことこそが、
元の重複ガードが一度も実行されなかった原因**だった。
`py_compile` は通り、実際に走らせて初めて `NameError` が出た。

→ **防ぎ方**: 構文チェックだけを smoke にしない。**実際に1回走らせる**か、
呼ぶ関数名を `grep -n "^def "` で実在確認してから書く。

### C-2. 却下プレートが motion 側にも居ることを確認しなかった
`P01.png` を外して満足し、`P01.mp4` を見なかった。
**willingham の film ビルドが2回、同じ理由で失敗した。**

→ **修正済み**: `_finish_episode.sh` が i2v コピー直後に img＋motion 両プールの
prune を必ず再実行する。手動でも `--pool img` `--pool motion` を明示して回す。

## D. 報告と計画のミス

### D-1. 受入ゲートの結果を末尾しか読まなかった
「不合格4件」と報告したが、**受領書には9件**あった。
4件ぶんのAPRを書いてから、もう1通書き直すことになった。

→ **防ぎ方**: `acceptance_receipt.v*.json` の `hard_failures` 配列を読む。
コンソール出力の tail を数えない。

### D-2. 測る前に直し方を宣言した
「必要な直しをして予約します」と言い、差し替えとスプライスの計画を立てた。
**実際の問題は素材の在庫そのもの**で、burge を正直に目視して初めて分かった
（244本中72本しか使えない／清潔かつ題材に合うのは2本）。計画が根拠を欠いていた。

→ **防ぎ方**: **1本を最後まで通してから**、残りの計画を立てる。
burge を1本通したら、6つのガードと素材の問題が全部見えた。

### D-3. ショートを一度も見なかった
丸一日チャンネルの話をしていたのに、オーナーに「画面を確認して」と言われるまで
**長尺しか見ていなかった。** 見たら1日2本予約されていて、取り決めは1日1本だった。

→ **防ぎ方**: 「チャンネルの状況」を報告するときは、
`yt_channel_index.py` の和集合で**全動画**を列挙してから話す。

### D-4. エージェント予算を管理しなかった
200体を使い切るまで残数を追わず、**6本が未審査のまま作業の途中で壁に当たった。**
予算のある資源だと最初から分かっていたのに、計画に入れていなかった。

→ **防ぎ方**: 目視のような並列前提の作業は、**着手前に必要体数を見積もる**
（1話あたりシート数 ÷ 2人体制）。上限が近づいたら、圧縮（per-source）に切り替える。
