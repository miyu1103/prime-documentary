## 1. EP69 hyatt was scheduled and broken. It is off the calendar now.

`Ms9wVUPsO3Y`, title "One Rod Became Two…", carried `publishAt 2026-08-23T03:00Z` while
`uploadStatus=uploaded` / `processingStatus=processing`, eighteen hours after upload, with
`duration P0D`, no custom thumbnail and no caption track. No local schedule receipt was ever
written.

**The trap, recorded because it nearly worked.** `videos.list` reported
`fileDetails.fileSize = 1644589283` — byte-for-byte equal to the local v002 master. I read
that as "the transfer completed" and was wrong. That number is the size **declared** in the
resumable session header, not the size **received**. `runs/upload_hyatt_0819.log` settles it:
twelve resume attempts from 1,292 MB to 1,334 MB, then `upload aborted after 13 network
failures`. YouTube had already applied the metadata sent in the session header, which is why
a video with no content read as scheduled everywhere.

**Root cause, measured:** two default routes at metric 0 — `Wi-Fi 2 → 10.40.210.161` and
`Ethernet → 192.168.210.1`, different subnets. Packets can move between interfaces
mid-connection and kill an established upload. Turning Wi-Fi off from the taskbar is enough
and needs no admin.

**Done:** `scripts/unschedule_video.py` (new) took it off the calendar without destroying it.
Guards demonstrated refusing a wrong title prefix and a public video before it was used.
**Its own read-back caught the first version lying** — a `status` part that OMITS `publishAt`
returns HTTP 200 and echoes the old date back unchanged; `publishAt: null` clears it. The
read-back must never be removed.

**Deleted, with owner approval, 2026-08-20 ~00:50.** `Ms9wVUPsO3Y` was still on the channel
29 hours after its aborted upload and was not going to be discarded on its own the way EP64's
was, so it would have blocked the re-upload's duplicate-title pre-check.
`delete_scheduled_video.py --apply` returned HTTP 204 and the API no longer returns the id.
The 08-23 slot is now empty and unobstructed.

**Armed:** `scripts/_reupload_hyatt_at_reset.sh` waits for the quota day (16:00 local),
refuses to start while two default routes are up (demonstrated), re-checks `decision=permit`,
stops for an owner decision if `Ms9wVUPsO3Y` has not been discarded by YouTube on its own
(EP64's was, within a day), and does not call the job done until the live API says
`processed`/`succeeded`. Quota at handover: **442 remaining of 10,000** — no upload fits today.
