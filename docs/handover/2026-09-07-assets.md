# Handover 2026-09-07 — the assets lane

Continues [2026-09-06](2026-09-06-shorts-and-assets.md). One job was scheduled for today: the last
644 Freesound rows. They were not the last 644 of a rate limit. They were a bug, and finding it
freed rows in three other sources that the record had written off.

---

## 1. "The next run retries it" was false

The belief, written down twice and inherited from 08-27, was that a rate-limited row keeps no
verdict, so the following day's run asks again. That is true of the **ledger**. It is not true of
the **resolver**, and the resolver is what does the asking.

Every per-source lookup in `resolve_item_licences.py` begins:

```python
for i in ids:
    if i in cache:      # <- a failure is in this cache too
        continue
    try:
        ...
    except Exception as exc:
        cache[i] = {"error": str(exc)[:70]}
```

A failed lookup was written into the same persistent cache as a successful one. **One HTTP 429
made a row permanently unanswerable.** Yesterday's batch hit the 2,000/day ceiling at row 1,993;
the remaining 644 were cached as errors, and today's run asked for **none of them**.

It was caught by not believing the summary. Today's run printed `unknown=644` — the same number as
yesterday, which is the shape of a thing that did not happen rather than a thing that failed. Three
of those ids, asked by hand with `curl`, answered **HTTP 200 with a licence**.

Failed lookups are now evicted before every run, and the count is printed
(`637 failed lookup(s) evicted for retry`) so this can never again be silent.

## 2. A CC-BY licence written as a URL was invisible to both patterns

The same rows exposed a second defect. Freesound answers with the licence **URL**, not its name:

```
https://creativecommons.org/publicdomain/zero/1.0/   -> FREE_PAT matches "publicdomain/zero"
https://creativecommons.org/licenses/by/4.0/         -> matched NEITHER pattern -> "unknown"
```

`BLOCK_PAT` looks for `cc-by`, and a CC-BY **URL does not contain that string**. So CC0 was
recognised in URL form and every reserved licence was not. The policy did not change — the file
has said since it was written that CC-BY, SA, NC and ND are "NOT promoted, on purpose" — it simply
was not being applied to the form the answers actually arrive in. Everything under `/licenses/` is
a reserved licence by definition; CC0 lives under `/publicdomain/`.

Demonstrated both directions, 13/13: CC0 URL and text free; `by`, `by-nc`, `by-sa`, `by-nc-nd`
URLs held; NARA's `Undetermined` still held; empty still unknown.

## 5. LOC is still blocked, and now that is a measurement

`wikimedia` and `nara` had been written off on the strength of a run the cache had silently
blocked, so **LOC's 2,724 could not be left on the same footing.** Re-asked today with the fix in
place — cache emptied, every id actually requested:

```
loc  2724 row(s), 0 cached ...
     free=0 held=0 unknown=2724
```

The lookup cache now holds **2,211 entries, every one of them `HTTP Error 403: Forbidden`**, which
matches a hand `curl` with a browser UA against `https://www.loc.gov/item/<id>/?fo=json`. LOC is
genuinely unreachable from here. It stays held, and that verdict now rests on an instrument that
was proven to work on the same day.

This is the one worth remembering: **three sources had been declared hopeless, and the difference
between the two that were wrong and the one that was right could not be seen until the instrument
was fixed.** A "no path forward" written from a broken tool reads exactly like one written from a
working tool.

## 6. The quarantine guard, implemented (owner said "やって")

Eleven themes are now **refused by name** in `search_archive.py` (`38a48696`), with the reviewer's
own note printed and `--allow-quarantined-theme` as the loud override. Four directions were
demonstrated before relying on it: refused (exit 3) / a good theme still returns 2,729 hits (exit 0)
/ override serves with a banner / keyword search unaffected and annotated with how many rows carry
a thrown-out label.

**Two things the survey got wrong, and only running the tools showed it.** The map said the
cheapest chokepoint was `factory_ledger_themes.select()`. In fact:

* `select_factory_assets.py --theme courtroom_justice` returns **0 rows** — that ledger does not
  exist on this machine and the tool already prints a four-line unverified banner. Nothing leaks.
* `search_archive.py --theme courtroom_justice` returned **3,045 rows silently.** That was the leak.

And `select_factory_assets.py` was left alone on purpose: three of its group names collide with
quarantined themes, but the factory shelf is a **different file population** — no `legal_court`
directory at all, groups derived from filenames, **0 basenames shared** with the archive shelf's
`legal_court`. Guarding it would have applied a verdict measured somewhere else. Full reasoning in
`docs/shelf/QUARANTINE_DECISION.v001.md` §7.

Keyword, `--shot` and semantic search are deliberately unfiltered: `--shot "courtroom interior
wooden benches"` returns a genuine courtroom *from* `courtroom_justice`. The material is real; the
label is what failed, which is also why nothing was deleted or moved.

**Not done — the erosion path.** `recover_stock_shelf.py` re-derives themes with no quarantine
check and the scheduled ingest runs `--theme all`, so these labels refill. The guard refuses the
question; it does not stop the shelf from answering it again tomorrow.
