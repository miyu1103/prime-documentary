## 4. この日程が崩れる原因、5つ（先に潰す）

### ① GPU の取り合い（一番大きい）
いま i2v とレンダーが同じ 4090 に乗っています（実測: 01:00 時点で ffmpeg 2 / node 3 が稼働中）。
**i2v の 36.7 clips/h はレンダーと競合した状態の値なので、この数字自体は安全側**ですが、
公開レーンが1日4本に上げると i2v はさらに落ちます。
→ **どちらを優先するか、日ごとに決めてください。** 8/26 は i2v 優先が得です（設計が追いつかないため）。

### ② EP85 の 4K化＋深度が未着手・担当未定
186枚すべて Codex から届いていますが、`remotion/public/katrina/img` は **0枚**です。
4K化（Real-ESRGAN）と深度生成をやらないと i2v にも組み立てにも入れません。
→ **私が回すか別レーンが回すか、決めてください。** これが決まらないと EP85 だけ日程から落ちます。

### ③ EP83 の深度が0
プレート188枚は4Kで揃っていますが `*_depth.png` が1枚もありません。②と同じ扱いです。

### ④ Codex の17枚が i2v より遅れると、二度手間になる
* EP77 差し替え16枚（H132–H147）
* EP82 V079（1枚）

i2v が終わったあとに届くと、その分だけ追加で i2v を回すことになります。
→ **EP77 は115枚でも成立します**（必要な映像素材は約110本、115 motion + 42 実写 = 157本）。
16枚は品質改善であって、出荷を止める要因ではありません。**間に合わなければ次版に回してください。**

### ⑤ EP80/81/82 の実写プールがゼロから
EP77 の歩留まりは18%でした。40本の床に届かない可能性があります。
→ 届かなければ **その時点で報告します。宣言値は下げません。**
　i2v が185本入るので映像比は満たせますが、実写ゼロの映画になる点は記録に残します。
