## 1. いま機械が何をしているか

**独立プロセスが1本動いています。チャットに依存していません。**

```
scripts/_chain_i2v_ep78_82.sh        (Start-Process で切り離し起動・親シェルが死んでも生存)

  話数ログ  out_i2v_<slug>.log           ← 1本ごとの ok / TIMEOUT

```

## 4. 踏んだ罠（同じ穴に落ちないため）

1. **GPU は1枚。二重起動は両方を壊す。** チェーンは `out_gpu_comfy.lock` を見て待つ。
   ロックを消して割り込まないこと。EP77 の作り直しと取り合いになり、通算10時間ぶん後退した。
   **他レーンが GPU を使うなら、待った時間はそのまま遅れになる。**
2. **毒プレート。** ComfyUI がプロンプトを受理してフレームを0枚しか出さない板がある。
   `is_done()` は false のままなので**次のチャンクでも先頭に来て**、600秒を捨て続ける。
   2回タイムアウトで自動隔離するようにした（concordia で2ラウンド＝20分を失ってから）。
3. **`set -u` の下で `local a="$1" b="${a}..."` は死ぬ。** キューがこれで無言で落ちた。
   stderr にしか出ない。起動したら必ず `out_i2v_ep78_82.err*` を見ること。
   `bash scripts/_chain_i2v_ep78_82.sh --selftest` が GPU を使わずに全ヘルパーを実走させ、
   `pending + delivered + quarantined = plates` の勘定を印字する。**起動前に必ず通す。**
4. **バックグラウンド起動は親シェルと運命を共にする。** `nohup ... &` で起動したキューが
   外部の SIGTERM で死に、10時間気づかなかった。`Start-Process -WindowStyle Hidden` で
   切り離すこと。
5. **フレームを消すと進捗カウンタが壊れる。** `reclaim_i2v_frames.py --apply` は全 slug を
   横断する。**話数の切れ目、GPU が空いている瞬間にだけ**回す（キューはそうしている）。
6. **`*_depth.png` は絵ではない。** `motion/` に1本でも入ったら事故。二重に塞いである
   （`collect_sources` の除外＋`comfy_wan.py:110` の数字アンカー glob）。それでも毎回数える。

## 5. 効いている設定（変えないこと）

`scripts/_chain_i2v_ep78_82.sh` の `BASE_PROMPT` と `neg_for()`。
話数ごとの否定語は `episodes/<EPID>/episode_spec.v001.json` の `forbidden_subjects` から
起こしている。**5話とも「事故そのものの瞬間」を否定側に入れてある。**

keybridge は組み込みの `SCENE_PROMPT`（"atmospheric living environment"）＋既定 neg
（"static, motionless" を否定＝フレームを埋めろという指示になる）のままで人物混入 27%。
concordia は上記で 0/182。**母数が違うので断定はしないが、差はここだと見ている。**
