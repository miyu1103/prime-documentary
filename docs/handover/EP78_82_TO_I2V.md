推奨の着手順は **80 → 81 → 82 → 78 → 79** です。

## 2. なぜ待たなくていいか

* **5話とも motion=0。EP80・81・82 は実写クリップが0本**なので、i2v が唯一の映像源です。
  ここが工程全体の律速で、止めておく理由がありません。
* ビルダーの構造アサーションは **カット150本以上・映像比62%以上**。
  27分を4.6秒刻みで埋めるなら約350カット、reuse≤2 なら **動く素材が約110本**要ります。
  各話の `distinct_video_assets: 252` は、**プレートを動かす前提でないと足し算が合いません。**
* 設計レーンはこれからプレートを1枚ずつ見ますが、**待つと5話が直列になります。**
  EP77 の実績で落ちたのは 131枚中16枚＝**12%**。仮に同率で無駄が出ても、
  **捨てるのは mp4 だけで、間違った絵が本編に入るわけではありません**
  （組み立ては台帳から引くので、こちらが「使わない motion」の一覧を出せば済みます）。
* 8/31以降のカレンダーが空いている以上、12%のGPUを余分に使ってでも並列化する方が得です。

「使わない一覧」が出ているか、直後に出ます。**

## 4. 全話共通のルール

* **`*_depth.png` は絵ではありません。** レンダラの入力です。
  過去に2回、深度マッテがそのまま本編に映って出荷されています。
  **`motion/` に `*_depth` が1本でも入ったらそれは事故です。**
* **i2v は「中身を変えずに生かす」範囲で。** 霧が流れる、水面が揺れる、光がちらつく、
  カメラがわずかに寄る。**新しい被写体を出さないでください。**
  実測された事故: 何も無いコンクリート壁にスーツの男が生成された／路肩に女性の顔が生成された。
* **`forbidden_subjects` を生成しないこと。** 各話の `episode_spec.v001.json` にあります。
  5話とも共通で禁止なのは、遺体・負傷・救助・葬儀・子ども・実在人物の顔・読める文書・
  ウォーターマーク・生成物であることを示すマーク、**および事故そのものの瞬間**です。
* この5話には **`img/rejected/` がまだありません**（設計レーンが未判定のため）。
  **`img/` の PNG を全部動かして構いません。** 落ちた分の一覧は後から届きます。

## 5. 返す前に必ず通してほしい検査

```
py -3.11 scripts/check_motion_saturation.py --slug <slug>     # exit 0 であること
```

* **BLACK-HEAD / BLACK-BODY が出たクリップは使えません。**
  EP75 lahaina は不良1本で 2時間30分の書き出しが無駄になっています。
* `motion/` に `*_depth` が無いこと。
* サンプルを抜いて、**終端フレームを元のプレートと見比べてください。**

### 不良を見つけたときの手順（片方だけでは戻ってきます）

finisher が `ae-demo` のフレームから作り直すため、**両方**やってください。

1. フレームディレクトリを **`ae-demo` の外へ移す**。
   **その場で改名しないでください** — 組み立てがディレクトリ名からクリップ名を作るので、
   別名の同じ不良品が復活します。
2. `config/footage_blocklist.v001.json` の **`blocked`** に episodes スコープ付きで登録。
   **`quality_deferred` は何も拘束しません**（そこに入れても素通りします）。
