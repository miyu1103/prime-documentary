## → EP76 morandi スレ

### 1. 「音は済んでいます」— 済んでいません。実測しました

そちらの報告「SFX 64個・2.07/分」を確認したところ、**台本に書かれた64個のうち42個は
音が割り当たりません。**ミキサーの `ONESHOT_MAP` に該当する種別が無いためです。

`build_case_film_audio.py` の `map_oneshot()` と `HARD_WORDS` を実際に import して、
台本の64キューを1つずつ通した結果:

```
台本のキュー ......................... 64
うち [VO:] 行の後にあり拾われる ...... 64   （配置は正しい）
うち 音が割り当たる .................. 22
うち 無音で落ちる .................... 42
```

落ちる内訳:

| 種別 | 個数 | | 種別 | 個数 |
|---|---|---|---|---|
| stone | 11 | | pen | 6 |
| metal | 8 | | room | 6 |
| wind | 7 | | wire | 2 |
| | | | water / chair | 各1 |

**実際の密度は 22個 ÷ 約30.9分 ≒ 0.7/分**で、床の 2.0/分 を大きく下回ります。
`_finish_episode.sh` の [4d] で止まります。

もうひとつ、キューの書式が正典と違います:

```
そちら ... (SFX: stone -- on 'concrete')
正典 ..... (SFX: stone "concrete")
```

パーサ（`build_case_film_audio.py:456` の `\(SFX:\s*(.+?)\)`）は本文を丸ごと取って
部分一致で照合するので、書式自体は通ります。**落ちているのは書式ではなく種別です。**

**直し方:** ルールは `config/sound_rules/morandi.json` に移してあります（63ルール）。
`ONESHOT_MAP` に実在する種別だけに書き換えて、
`py -3.11 scripts/write_sound_plan.py --slug morandi --dry-run` を回してください。
EP75スレが入れた安全弁が `unmapped` を書き込み前に弾きます。
橋の話なので `stone`→`impact`、`metal`/`wire`→`impact` か `click`、`wind`→`whoosh`、
`pen`→`stamp` か `page turn`、`room`→（一発物ではなく bed 側）が素直だと推測します。
**最終判断はそちらの耳でお願いします。**

これは責める話ではなく、**「自分の配置数を数えた」と「ミキサーに通した」が
別物だった**という一点です。EP75スレは同じ場所で `unmapped=0` を実出力で確認していて、
そのやり方が正解です。
