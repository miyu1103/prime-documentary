## 1. 至急：solve_totals の入力に使った 326 は、目視を通った本数ではありません

そちらの計算：

```
i2vなし  399カット / 4.73秒per cut  (factory枠 277)
```

これは **factory 326本が全部使える** 前提だと思います。**目視を始めたら、そうなっていません。**

44枚のシートのうち3枚（18本）を6コマで見た実測：

| シート | 採用 | 却下 | 却下の中身 |
|---|---|---|---|
| 1/44 | 2 | 4 | 線香花火・寝室でスマホを見る人・古典建築の前で踊る男・机で電話する男 |
| 30/44 | 2 | 4 | 南欧の鎧戸と街路・手影絵のうさぎ・ギリシャ語の政治ポスター・すりガラスに押し当てた手 |
| 40/44 | 0 | 6 | 3Dの地球儀・霧の森・商業モール・過度なシアン加工・**縦動画2本** |

**採用 4 / 18 = 22%。** これを261本（タイトル選別後）に当てると **約58本**です。

`solve_totals(1886.8, 58, 0, 120)` は 7.4秒/カットになり、上限6.0秒を超えます。

**3枚で22%が3回続いたので、結論は動かないと見ています。**ただし残り41枚も見ます。
見終わったら実数をお送りします。**その数字で計算し直していただけますか。**

### 却下の中身が原因を語っています

短い語は数を稼ぎますが、意味が散ります。

```
light   → 線香花火
phone   → 寝室でスマホを見る人
camera  → 電話中の男の顔（"towards the camera" にも当たる）
alley   → ボウリング場（bowling alley）
stairs  → 階段で踊る男
```

**「alley」の誤義はこれで3種類目**です（並木道 / ボウリング場 / 本来の裏路地）。

一方、2語は的中率が高いです。第1波の実測で `seoul night` `night alley` `subway seoul` は
ほぼ全部が使えるものでした。**5語は0件、1語は的外れ、2語が最適**という形になっています。

不足分の埋め方について、i2v を使わない前提での案を2つ出します。**判断をお願いします。**

- **案A**：`stage_footage_by_title` に**2語クエリを大量に**投げ直す（`seoul night` `night alley`
  `wet street` `subway station` `empty corridor` など50〜80語）。GPU不要、1〜2時間。
- **案B**：58本で成立させ、`target_cut_sec` の逸脱を `release_deviations` に記録して出す。
  ただし7.4秒/カットは紙芝居側に寄るので、私は勧めません。
