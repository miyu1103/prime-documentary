## 2. 制約（破ると事故になるもの）

### 2.1 投稿本数の上限＝**1日6本**
YouTube Data API の1日割当が10,000ユニット、`videos.insert` が1本1,600ユニット。**10,000÷1,600＝6.25本**が物理上限です（増枠申請は別途可能）。

### 2.2 BANされる条件は「本数」ではなく「中身」
- 本数自体は違反ではありません
- 危険なのは **mass-produced / repetitive content**（同一テンプレの詰め替えが見て分かる状態）
- 対策：**1本ごとに素材・構成・フックを変える**。テンプレの使い回しが視覚的に分かる状態にしない

### 2.3 肖像・権利
- **実在人物の写真・肖像は使用禁止**（AI生成の非実在キャラクターのみ）
- 素材は商用利用可のみ（`H:\pd-media\assets\archive\_ledger\*.jsonl` に台帳。112,678点、`scripts/search_archive.py` で検索）
- AI画像・AI音声であることの開示を概要欄に入れる

### 2.4 事実性
- 実在の事件を扱うため、**台本の全主張は一次資料に基づくこと**
- 係争中・存命の人物への断定を避ける（「〜と裁判所が認定した」の形にする）

## 3. 既存の制作規約（SHORTS_METHOD v001 の要点・そのまま守る）

1. **1秒フック**：イントロ・ロゴ・「この動画では」禁止。最も衝撃的な一行から始める
2. **パッケージング優先**：カバーフレーム＋最初の一行＋タイトルを、作る前に決める
3. **オープンループ→ペイオフ**：冒頭で問いを立て、答えは最後に出す
4. **尺は20〜40秒**（60秒まで可、ただし埋めない）
5. **ループ設計**：最後のフレームが最初に自然に繋がる
6. **ミュート前提**：大きな speech-sync 字幕。**1〜2秒ごとに視覚的な切り替え**（静止2秒超は禁止）
7. **顔と感情と動き**：フックとペイオフには必ず感情のある顔か強い動きを置く
8. **勝った型は反復**（同じ型で事件を差し替える＝シリーズ化）
9. **登録導線**：口頭＋画面のCTA、長尺への誘導（「全編はチャンネルで」）
10. **一貫したペルソナ**：同じ声・同じ字幕スタイル・同じマーク
11. **3プラットフォーム書き出し**：YouTube Shorts / TikTok / Reels（UI安全域を考慮）
12. **公開後は離脱グラフを読む**：次の1本で、離脱した瞬間を直す

## 4. このスプリントで実行してほしいこと

### 第1週：**1日3本 × 7日 = 21本**、フックの型を3種でA/B

本数を6本に増やす前に、**どの型が突破するか**を特定します。3本/日なら1日で3型を同時に試せます。

#### 型A：二人称の脅威（Law By Mike 型・93M再生の型）
```
「もし警察に○○と言われたら、あなたは答えなくていい」
→ 実際の判例で何が起きたか
→ 「知らなかったら終わっていた」
```

#### 型B：数字の落差（stakes-gap）
```
「2ドルの検査キットが、彼女から21日間の自由を奪った」
→ 経緯
→ 「そして416件で同じことが起きていた」
```

#### 型C：当局の一言（引用フック）
```
「『あなたは男性乳がんです』——結婚18周年の日に医師が言った言葉」
→ なぜそれが起きたか
→ 「基地は水質を測定し、記録し、蛇口を開けたままにした」
```

**各型を1日1本ずつ、7日間。合計21本。** 公開48時間後の再生数を型ごとに集計し、勝った型に寄せます。

## 10. 追記（2026-08-01・素材スレより引き継ぎ）

このv001が書かれた後に、別スレで実測・実装したものです。**着手前にここまで読んでください。**

### 10.1 冒頭の離脱を実測した（規約3-6「1〜2秒ごとの視覚切り替え」の根拠）

公開済み長尺のYouTube維持率カーブ21本を横断解析した結果:

- **21本中19本(90%)が、動画全体の最初の2%以内で最大の離脱**を起こしている。尺と無相関(r=-0.21)
- **半減は44秒**（範囲17〜133秒）
- 10%以降のカーブはほぼ平ら（25%地点22.8% → 最後11.6%）＝**本編は保っている。冒頭だけが殺している**
- 全動画が `rel_perf_30s` 0.16〜0.27（基準0.5）＝同種動画の**4分の1**しか残らない

最良と最悪の冒頭30秒を実際にフレームで並べた結果、差は**言葉ではなく画の切り替わり回数**だった:

| | 30秒間のテロップ枚数 | 画 |
|---|---|---|
| 100%残存 (flashcrash) | **約8枚**（2秒ごとに全入れ替え） | 2秒ごとに別の絵 |
| 92%残存 (rolin) | 2〜3枚 | 2秒ごとに別の絵 |
| 40%残存 (hinders) | 3枚を各6〜8秒保持 | 暗い・ほぼ静止 |
| 39%残存 (arbitration) | **1枚を30秒間ずっと** | ほぼ静止 |

原稿は4本とも同じ型（二人称・具体・不正義の提示）で、**文章の質では差がつかなかった**。

**ショートに落とすと**: 1枚のテロップを4秒以上出さない。長文を読ませない（`998.5 POINTS` のような短い単位で叩く）。同じ絵を4秒以上引かない。暗い画だけで始めない（上位2本は赤・金・青・緑の輝度が入る）。

### 10.2 素材検索が変わった（§6-5と§7の1行目を置き換える）

```
py -3.11 scripts\search_archive.py --shot "prison cell corridor" --kind video --sheet
```

- `--shot` … カット説明でランク検索。トーキングヘッド減点、実在ファイルのみ、**常用語だけの一致は不採用**（"exterior"だけで郊外の一軒家が出る問題を潰した）
- `--sheet` … 候補を**ラベル付きコンタクトシートに自動生成**。見て選ぶまでが1コマンド
- `--pick 1,3 --reject 2,4` … 目視結果を記録。次回以降の順位に反映（採用+15／却下-25）
- `--md` … 設計書に貼れる表形式

実証: prison検索12件 → 目視で使えたのは5件。却下の中に**フレームにFOX NEWSロゴが焼き込まれた放送素材**が混ざっていた（タイトルに局名が無くパターン走査では捕まらない）。**§7の「台帳のタイトルで選ぶ」でも不十分。絵を見ること。**
