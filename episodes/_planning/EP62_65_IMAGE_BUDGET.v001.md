## 2. 枚数の計算

契約値は各話 `distinct_video_assets = 234`（`episode_spec.v001.json`）。導出は尺 × 0.65 ÷ 4.5 で、`docs/PD_EPISODE_SPEC_STANDARD.v001.md` が**半分にするなと明記**しています（EP54が半分にして253カット中65回の使い回しになった）。

**ここが決定的です。** `check_spec_satisfied.py` が数えるのは

```
distinct_video_assets = 実写(factory で accept) + モーション(remotion/public/<slug>/motion/*.mp4)
```

で、**静止画は1枚も数えません**。静止画は `stills_in_film` という別の欄に出ます。つまり**絵を発注しただけでは契約を満たせず、動かして初めて資産になります**。これはオーナーの「紙芝居禁止」「ズームとパンだけは紙芝居」という指示と同じことを、機械の側から言っているだけです。

### 各話の必要枚数

| | 契約 | 実写(採用) | **発注する画像 = 契約 − 実写** |
|---|---|---|---|
| EP62 `greene` | 234 | 12 | **222枚** |
| EP63 `correa` | 234 | 11 | **223枚** |
| EP64 `memphis` | 234 | 24 | **210枚** |
| EP65 `marmet` | 234 | 15 | **219枚** |
| **計** | | 62 | **874枚** |

**この密度は前例の範囲内です。** EP60（40分）は同じ規則で **279枚・変種0・指定外0・sha256重複0** を1周で達成しています。29分の話で210〜223枚は、EP60と同じ1分あたり密度です。

### 動かす（これをやらないと数字が資産にならない）

発注した画像は **1枚 = 1モーションクリップ**として `remotion/public/<slug>/motion/` に書き出します。手段は既存のもので、新規実装はしません。

- **i2v（Wan2.2 5B / ComfyUI API・`ae-demo\comfy_wan.py`）** — 実証済み。人物が破綻しないのが確認済みの本命。
- **深度パララックス（`gen_depth_maps.py` → `DepthImage`）** — 長尺 CaseFilm に統合済み（EP29）、ショート `Short.tsx` にも統合済み（EP32）。
- **Ken Burns（ズーム/パンのみ）は不可。** オーナーが紙芝居として却下済み。動いているかは連続フレーム差分で実測してから出します。

## 3. 1話1バッチ（EP60の5バッチ膨張を繰り返さない）

EP60でバッチが5本に膨らんだ原因は3つとも同じで、**発注時点で構造が決まっていなかった**ことでした。EP61は先に測って1バッチで完結しています。今回も同じ順です。

1. 8区分（HOOK / OP / ACT_1〜5 / ENDING）に割り、**区分ごとに枚数を確定してから**プロンプトを書く。どの区分にも絵がある状態にする。
2. **1プロンプト = 1枚。** `_02` `_03` を作らない。「良いのが出るまで回す」を禁止する。
3. 人物プレートは各話 **10枚以上**（`people_plates_min: 10`）。実在肖像は禁止、全員「実在しない一般人」として描く。
4. サムネ候補は各話 **3枚以上**（`thumbnail_candidates_min: 3`）。
5. **ショート12本のプレートは同じ発注に含める。**`SHORTS_SLATE_EP62-65.v001.md` の各ショートが要求するモチーフは、上の222/223/210/219枚の内数です。ショート用に二度目の波を出しません。
6. **ブリーフを書いた瞬間に `mandatory_stills` を埋める。**空のままにすると `check_spec_satisfied.py` の唯一の保護が無効になります（EP54は、棚に法廷映像が無いから作らせた14枚が完成品から消えたのに誰も気づきませんでした。EP61も空欄のまま引き継いで後から埋め直しています）。

## 4. オーナーの判断が要る1点

**874枚は、この4話を契約どおりに作る場合の数字です。**

出荷済みのエピソードは1本も234に届いていません（実績137〜193）。つまり `asset_reuse` は EP57/58/59 で実際にハード不合格になっており、**赤が常態**でした。選べるのは次の2つです。

| | 中身 | 結果 |
|---|---|---|
| **A（推奨）** | 874枚を発注し、全部モーション化する | 4話とも契約を満たす。チャンネルで初めて `asset_reuse` が緑になる |
| B | 各話150枚に抑える | 各話の distinct video は約165。**約70本不足**し、レンダー後に `footage_diversity` と `asset_reuse` が落ちる。承認済み偏差として記録する必要がある |

**Aを推奨します。**理由は3つ。①密度はEP60の前例どおりで未知ではない。②不足は必ずレンダーの**後**に出るので、Bを選ぶと作り直しが1回増える（「同じ失敗を仕組みで防ぐ」に反する）。③この4話は実写が26%しか生きておらず、絵を削ると本当に紙芝居になる。
