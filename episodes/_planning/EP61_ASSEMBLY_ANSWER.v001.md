## 2. `mandatory_stills` 150枚について

### 2.1 認識は違います。実装がそう書いてあります

`scripts/check_spec_satisfied.py`：

```python
# 1. Every purpose-made still is on screen. This is the EP54 failure, made impossible.
mandatory = list(spec.get("mandatory_stills") or [])
missing = [s for s in mandatory if _basename(s) not in present]
if missing:
    failures.append(
        f"mandatory_stills: {len(missing)} of {len(mandatory)} declared still(s) are in no "
        f"cut of the film -- ... These were generated FOR this episode to cover a gap the "
        f"archive cannot fill; a film without them has a hole where the coverage was "
        f"supposed to be.")
```

- 照合は `film.json` の全カットの `src` の **basename 集合**に対して行われます。
- **1枚でも欠けたら `failures` に入り、`exit 1`** です。
- docstring の一行目が意図そのものです：*Every purpose-made still is on screen. This is the EP54 failure, **made impossible**.*

「消えたら検出できる」ではなく「**消えていたら通さない**」。EP54は、棚に法廷映像が無いから作らせた14枚（S211–S224）が余剰トリムでアルファベット順の末尾ごと消え、完成品に法廷が1つも無いまま誰も気づきませんでした。その再発を不可能にするための検査です。

### 2.2 したがって「105枚しか入らないのは想定内」は成立しません

いまの構成のままなら、`check_spec_satisfied.py` は **45枚不足で必ず落ちます**。

### 2.3 ただし工具を緩める必要はありません — 算数で解けます

```
必要カット数 = 150 ÷ 0.32 = 469カット

27.0分 (1620s) → 1620 / 469 = 3.45 秒/カット
30.0分 (1800s) → 1800 / 469 = 3.84 秒/カット
32.0分 (1920s) → 1920 / 469 = 4.09 秒/カット
```

**いまの4.5秒・330カットで入らない原因は、`MIN_VIDEO_SHARE` ではなく尺が25分であることです。**

- 契約帯の上寄り（32分）なら **4.09秒平均**で150枚が入ります。いまの4.5秒からわずか0.4秒縮めるだけです。
- 30分なら3.84秒。これも極端ではありません。

**①と②は同じ問題です。**尺を伸ばせば両方同時に解けます。

しかも刻みを4.5→3.8秒に縮めるのは、オーナーが繰り返し出している指示（紙芝居禁止・カットを刻んで実際に動かす・`animation_density` が緑でもアニメが少ない）と**同じ方向**です。**受入基準を1つも緩めずに済みます。**

### 2.4 もう一つの解 — 静止画を動画にする（EP62〜65で私が採った道）

`MIN_VIDEO_SHARE` が数えているのは**ファイルが動画かどうか**です。静止画を i2v（Wan2.2 5B・`ae-demo\comfy_wan.py`）や深度パララックス（`gen_depth_maps.py` → `DepthImage`）で**モーションクリップにすると、動画側に計上されます**。そうすると比率の衝突そのものが消えます。

私はEP62〜65で同じ判断をしました。理由は `check_spec_satisfied.py` の3番目の検査です：

```python
videos = {n for n in names if n.lower().endswith(VIDEO_SUFFIXES)}
need = int(spec["distinct_video_assets"])
if len(videos) < need: ...
```

`distinct_video_assets`（EP62〜65は各234）は**実写＋モーションだけ**を数え、**静止画は1枚も数えません**。つまり絵は動かして初めて資産になります。だからEP62〜65は「契約234 − 実写採用 = 発注枚数」（222/223/210/219＝計874枚）を**全部モーション化する前提**で発注しています。

**⚠ ただしEP61でこれをやる場合の罠**：`mandatory_stills` は **basename 完全一致**で照合します。`W001.png` をモーション化して `W001.mp4` にすると、`_basename("W001.png")` は `present` に無いので**照合が外れて落ちます**。

対処は「拡張子を無視して stem で照合する」への検査側の修正です。これは**基準を緩めるのではなく、同じ絵を別の器で運んだことを認識させる**修正です。とはいえ受入検査に触るので、オーナー承認を取ってからにしてください。

### 2.5 あなたの提案（実測の動きで判定）について

**方向は正しい**と考えます。オーナーは以前から「`animation_density` が緑でもアニメが少ない／ゲートは"凍っていない"を測っているだけ」と言っており、光学フローのような**動きの大きさ**で下限を持つべきだ、という指摘が既に出ています。

**ただし1点だけ強く反対します。実写比率の下限を下げる根拠には使わないでください。**

`MIN_VIDEO_SHARE = 0.68` は「動くものを作らせる」圧力そのものです。実測モーション検査に置き換えると、「静止画にゆっくりズームをかけて動き指標を最低限満たす」が通り得ます。それはオーナーが名指しで却下した紙芝居（Ken Burnsだけ）です。

推奨は**追加であって置換ではない**形です：

- `MIN_VIDEO_SHARE` は据え置く
- 60秒プローブの `motion_energy` / `animation_density` / `motion_density` は**追加の下限**として入れる
- 静止画主体を許す条件にはしない
